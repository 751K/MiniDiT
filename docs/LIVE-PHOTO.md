# 实况照片

MiniDiT 可以从已能在本机播放的视频中选择一段内容，生成实况照片。适合取出一个动态瞬间，或将拍摄时标记的 Shot Mark 批量导出。

## 使用

- 来源素材：在主界面右键点击视频，选择「导出实况照片…」。也可打开视频预览，在想保留的画面暂停后，通过控制栏右侧的导出菜单进入。Wi-Fi 视频沿用预览的缓存和原片确认流程；准备好素材后自动进入编辑器。
- 已导入素材：进入项目，右键点击视频，选择「导出实况照片…」。原卡无需在线。

时间轴显示整个源视频：拖动中间的封面点选择画面，拖动两侧 In / Out 手柄调整片段范围，高亮区间就是预览与导出的内容。首次打开默认选择约 3 秒，之后可以缩短或加长；范围始终位于源视频内，最短 0.5 秒。点击「预览」播放选中的片段，结束后回到封面。

不使用 Shot Mark 时，在时间轴上方的「片段」菜单中选择「添加片段」，可创建第二张或更多实况照片。新片段沿用当前范围作为起点；分别调整封面及 In / Out，通过「片段」菜单切换编辑或移除当前片段。点击「导出 N 张…」或「存入照片」会处理全部手动片段。手动片段与 Shot Mark 模式分别保留选择，切换模式不会清空已编辑内容。

开启「按 Shot Mark 批量导出」后，每个有效且不重复的标记生成一张；可切换标记预览，并为每个标记分别调整范围和封面；切回单张导出时保留原先的单张选择。导出前就已位于视频之外的标记不会生成额外照片。

## 两种格式

**Apple Live Photo**：每张生成一个独立文件夹，包含配对 JPG/MOV。图片标识与视频内容标识相同，MOV 内保存封面时间。可以点击「存入照片」将配对文件作为一个资产添加到苹果“照片”，再从“照片”中分享。仅导出文件时，不请求照片权限；不要把 JPG 和 MOV 当成两份互不相关的资源分别转存。

**Motion Photo**：生成名称以 `MP.JPG` 结束的单个文件，其中包含封面、Motion Photo 1.0 元数据和 MP4 视频，供支持该格式的设备或应用使用。接收设备或社交软件可能将其显示为普通图片或视频，不能仅凭文件扩展名推断动态效果仍然保留。

## 画质与原文件

输出最高 4K、60fps，使用 H.264、SDR 和 AAC 音频（源视频有可解码音轨时）。竖屏方向保留；HDR 输入转为 SDR，不生成 HDR 实况照片。Log 不自动套 LUT 或调色。

使用的是当前预览文件：如果它是代理，窗口会注明代理画质。系统无法解码的视频需要先通过可用的剪辑/转码工具生成可播放文件。

知道拍摄时间时，沿用原视频的时间并加上封面在源片段中的位置；不知道时不编造拍摄时间。存入“照片”时保留包含源文件名的资源名称。

生成的文件是独立派生内容，不改变原片、项目导入记录、备份或校验基准。同名结果不会被覆盖。取消或失败会删除未完成的临时文件，批量导出中已经完成的文件保留。存入“照片”在全部文件准备完毕后提交；系统提交期间需等待结果。

## 验证范围

已通过合成素材与本地真实 4K H.264/PCM 视频导出检查。Apple 文件经过 PHLivePhoto 系统识别；Motion Photo 检查原生 XMP、JPEG 可读性及内嵌 MP4 的位置与可播放性。另覆盖封面时间、音轨、竖屏、短片、HLG 输入、取消清理、同名保留及源文件散列不变。手动多片段已验证两张输出各自的范围、封面与系统识别，以及切换、移除草稿时不删除已导出文件。自选范围已验证 4.4 秒 Apple Live Photo 的系统配对识别、实际时长与封面时间，以及 1.2 秒 Motion Photo 的内嵌视频范围。

测试未向用户照片图库添加资产。iPhone/Android 相册和各社交软件的分享往返仍需实机验证。

接口依据：[Apple Live Photo 保存](https://developer.apple.com/documentation/avfoundation/capturing-and-saving-live-photos)、[配对资源识别](https://developer.apple.com/documentation/photos/phlivephoto)、[Motion Photo 1.0](https://developer.android.com/media/platform/motion-photo-format)。
