# 后期软件发送与重试

Resolve、Premiere Pro、Final Cut Pro 或剪映发送失败后，在「项目 › 导入记录与备份 › 后期软件」选择对应软件的「重试发送」。本批导入完成提示也提供重试入口。已保存的文件和已完成的备份不重新传输；原卡无需保持连接。

## Resolve

目标是与 MiniDiT 项目同名的 Resolve 项目，项目名在导入完成时冻结在本批记录里。脚本先看当前打开的项目是不是它；不是就从项目库根目录逐层查找同名项目并打开，找不到就在根目录新建。切换前保存当前打开的项目（未命名的临时项目除外），导入完成后保存目标项目。

第一次发送后记录 Resolve 返回的项目唯一标识。重试按名字找到项目后核对标识：原项目被删除时不会自动重建，同名但标识不同的项目也不能作为原项目使用。首次发送在 Resolve 应答前失败、尚未绑定项目时，重试仍按冻结的项目名查找或新建。

发送前检查工作文件与代理是否可访问、大小是否与记录一致，以及可取得的卷标识是否匹配。这是发送预检查，不重新读取整段素材计算校验值，也不代表一次新的内容核验。

脚本查找整个项目的媒体池，按实际文件身份或规范路径识别已有素材。用户将片段移动到其他媒体夹后仍能识别；部分导入成功后只加入缺失文件。重复发送不会创建相同文件的额外片段。重试继续按本批记录处理时间码、卷号、输入色彩空间、Shot Mark 和代理关系；标记位置已有其他用户标记时保留原标记并报告。

结果分别记录未加入文件和拍摄信息警告。导入过程中若项目被切换，立即停止，不将视频发往其他项目。后台脚本按项目串行处理；无响应超时只停止 MiniDiT 自己的脚本进程，不结束 Resolve。

## Premiere Pro

需要 25.6+ 和 MiniDiT UXP 插件面板（插件 1.1.0）。目标是与 MiniDiT 项目同名的 .prproj，位置在导入完成时定下来并冻结在本批记录里：先用 Spotlight 找已有的同名项目文件（几个时取最近修改的），没有就定在「影片」文件夹。插件发现当前打开的就是它就直接用；文件已存在就打开；不存在就新建。导入完成后保存该项目。PR 可以同时打开多个项目，打开目标项目不会关闭用户正在用的项目。

第一次发送后记录 PR 返回的项目 GUID；重试按冻结的位置打开项目后核对 GUID：原项目文件被删除时不自动重建，被换成另一个同名项目时拒绝发送。导入过程中目标项目被关闭则停止；切换到其他项目不影响向目标项目导入。旧版本创建、没有目标项目的发送记录，重试时仍发往当前项目并核对原 GUID。

按照 MiniDiT 项目和卷号建立素材箱，从整个 PR 项目查找已存在的文件。仅加入未找到的素材；按 API 实际可取得的文件身份或规范路径去重，不按文件名去重。代理不作为另一条原片导入，而是关联到原片；已有不同代理与相同位置的用户标记不覆盖。原始文件的嵌入时间码由 PR 读取；当前版本不重写 PR 时间码、卷号元数据或色彩设置。

PR 逐文件接收结果、代理/标记警告与主文件存储结果分别记录。重试使用原计划，不重新下载，也不建立时间线。更多使用方法见 [Premiere Pro 连接](PREMIERE.md)。

## 剪映专业版

剪映没有脚本接口，交接方式是草稿文件。目标是剪映默认草稿位置（`~/Movies/JianyingPro/User Data/Projects/com.lveditor.draft`）里与 MiniDiT 项目同名的草稿：

- 没有同名草稿：新建一个，原片登记在素材区（不含代理），时间线留空，画布按第一个片段。先写到隐藏的临时文件夹，写完再改名，剪映不会看到写了一半的草稿。
- 有同名草稿且剪映还没打开过它：把本批片段加进素材区，已有的片段不重复加入。剪映在首页列出草稿时会给草稿信息补字段，但仍是明文，MiniDiT 保留这些字段。
- 同名草稿已在剪映里打开过：剪映 6 起会把打开过的草稿加密，MiniDiT 读不懂，也不应改写。此时不新建、不改动，结果标为「需处理」，提示在剪映中手动导入这些片段。剪映的加密格式没有公开，MiniDiT 不尝试破解。

草稿名、片段路径、时长、尺寸和帧率在导入完成时冻结在本批记录里；重试按同样的规则处理，不会重复加入。已在剪映专业版 11.7（macOS）上验证：新建草稿、向列出但未打开的草稿追加片段、打开后的草稿被加密。草稿结构参照 pyJianYingDraft（Apache-2.0）整理的字段，没有复制其代码。

## Final Cut Pro

「设置 › 视频 › 导入至 › Final Cut Pro」里可以选 MiniDiT 项目在 FCP 中作为什么：

- **资源库**（默认）：与 MiniDiT 项目同名的资源库，每个视频文件夹一个事件。先用 Spotlight 找已有的同名 .fcpbundle（几个时取最近修改的），没有就定在「影片」文件夹。
- **事件**：所有片段放进你选定的资源库（默认「影片」文件夹里的 MiniDiT.fcpbundle）中与 MiniDiT 项目同名的一个事件。原来的视频文件夹（例如卷号）写成覆盖整段片段的关键词，FCP 会据此生成关键词精选，原来的分组不会丢。关键词需要片段时长：相机 XML 里有就用，没有就从视频文件读取。

FCPXML 的导入选项（`library location`）指定上面定下的资源库。该位置没有资源库时 FCP 会新建；资源库已存在但没打开时 FCP 会打开它；事件按名字归入已有的同名事件，带相同素材标识的片段不重复加入。FCP 直接导入，不再询问放进哪个资源库。资源库位置在导入完成时冻结在交接文件里。已在 Final Cut Pro 12.4 上实测：第一次新建资源库和事件；关闭资源库后再次发送，FCP 重新打开同一资源库，新片段进入同一事件，已有片段没有重复；「事件」方式下第二个项目在同一资源库里成为新事件，关键词精选按卷分组。实测还确认：关键词不写时长时精选为空；同一文件若以不同的素材标识再次导入，FCP 会拒绝整份文件，MiniDiT 的素材标识由文件路径和内容校验值决定，同一文件始终相同。

每次导入保存原始 FCPXML 内容。明确发送失败后，重试使用相同文件名、相同字节及稳定的素材/事件标识；之后更改 MiniDiT 偏好或素材附属 XML，不改写原发送计划。交接文件被手动修改后，不静默覆盖。

macOS 的打开回调只说明打开请求是否成功提交，无法证明用户完成了资源库导入。因此：

- 明确失败：提供「重试发送」。
- 请求成功：显示「已发送到资源库“项目名”，请在 Final Cut Pro 中查看导入结果」，不自动重发。
- MiniDiT 在发送时中断：显示接收结果无法确认，不自动重发。
- 已发送或结果未知：提供「显示交接文件」，在访达中定位原 FCPXML，由用户检查并按需操作。

MiniDiT 不从打开成功推导资源库导入成功，也不承诺跨资源库没有重复条目。

## 持久化与隔离

`ImportBatchRecord.videoDeliveries` 与文件结果一起保存在项目导入日志。记录包含文件大小和卷标识、冻结的发送内容、所属项目、尝试标识、时间、Resolve 项目标识和最后结果。新一次导入不覆盖旧批次的发送记录。正在发送和已排队的同一记录不能重复启动；旧批次结束不会改写新批次的完成提示。

重启不自动启动后期软件。未开始发送的记录恢复为可手动重试；发送中的 Resolve 记录恢复为中断，FCP 记录恢复为结果未知。无法保存记录时不继续调用外部软件。

本入口覆盖新导入的 Resolve/PR/FCP 发送计划。Capture One 与 Lightroom Classic 沿用已有接收机制；旧记录没有保存原始计划时，不根据当前设置猜造历史发送内容。CLI/MCP 当前可以查询 `sendingVideo`，尚未提供视频发送重试操作。

## 验证范围

`VideoDeliveryTests` 验证状态、持久化和文件预检查；`--video-delivery` 应用检查使用真实临时文件和软件 API 替身，验证导入、失败、恢复与界面。生产 Resolve 脚本的媒体池逻辑使用确定性的 API 替身执行。现有项目导入约束和多目标备份检查同时通过。

上述检查不等于真实 PR 软件端实测。Resolve、FCP 和剪映的按名字查找或新建已在真实软件上实测；FCP 是否导入完成仍由用户在 FCP 中查看。
