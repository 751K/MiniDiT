# MiniDiT 功能清单与实测记录

每项功能的实现要点和实测情况。面向开发者；使用说明见 [README](../README.md)。

**实机**：A7 V（ILCE-7M5）连家里的 Wi-Fi，开着访问身份验证（SSH）。没有实机条件的部分用模拟相机（`swift run fake-sony-camera`）或做的测试卡测。

| 设置向导：第一次打开时按步骤选使用方式（个人 / 专业）、照片导入方式和位置、视频位置、是否备份；「设置 › 通用」里可以重新打开。个人方式隐藏命名模板、卷号、Resolve 色彩空间等不常用的设置 | ✅ |

| 命名模板：会话名、下载文件夹、备份文件夹各一个模板（`{YYYY}` `{MM}` `{DD}` `{M}` `{D}` `{事件}` `{场次}`），在「设置 › 照片 › 命名」里改（备份文件夹在「设置 › 备份」） | ✅ v0.4 |
| 导入到 Lightroom Classic：照片下载、校验后由 MiniDiT 插件逐张加入 LrC 当前目录，每组一个收藏夹（收藏夹集「MiniDiT」），RAW+JPG/HIF 自动叠放；插件在「设置 › 软件」里一键安装 | ✅ v0.4，LrC 15.6 实测 |
| 「只下载」导入完成后用访达、Adobe Bridge 或 DxO PhotoLab 打开下载的文件夹（一天就是那天的文件夹，几天就是上一层） | ✅ v0.4，访达、DxO PhotoLab 10 实测；Bridge 未实测 |
| 大图预览显示拍摄参数：焦距、光圈、快门、ISO、曝光补偿、机身和镜头（读卡器读原文件，Wi-Fi 读相机给的预览图） | ✅ |
| 按时间间隔分场次（默认不分，可在设置或侧栏右键里打开）：同一天相邻两张隔得比设定久就分成两场，场次可以单独查看和勾选 | ✅ v0.4 |
| 多来源同时导入：在当前相机 / 存储卡之外再打开其他存储卡（侧栏来源卡片 › 「同时打开此存储卡」），按拍摄时间合并显示，可按来源筛选；RAW+JPG 只在同一来源里配对；导入时每个来源一个子文件夹（「α7 V/」，同机型加卷名区分），文件名不改；导入记录按机身分开 | ✅ v0.5，Wi-Fi 相机 + 两张卡实测（模拟卡） |
| 同时连接多台 Wi-Fi 相机：侧栏来源卡片里点连过的相机（「同时连接此相机」）或「输入地址同时连接相机…」；每台相机各自连接、断线后各自自动重连（照片和选择保留）；导入中途某台掉线会中断，重连后「继续导入」；导入记录按各自的机身 ID；同一台相机（同一地址）不会连两次；第二台不会抢「启动时自动连接」的位置 | ✅ v0.5，真机 a7 V + 两台模拟相机实测 |
| 相机档案（菜单栏「来源」或右键来源）：重命名（「主机」「副机」，也用作多来源导入的子文件夹名）；Wi-Fi 相机可设为只导卡 1 / 卡 2；按机身记住，存储卡读不到机身序列号时按卡记住 | ✅ v0.5 |
| 时钟对齐：打开两台以上相机时提醒「相机时间尚未对齐」；选中两台相机同一时刻的各一张照片，「按这两张对齐时间」，记下时差，合并显示按校正后的时间排序 | ✅ v0.5（相机自己的时钟在 a7 V 上读不到：不支持 PTP 读属性 0x1015） |
| 每台相机看哪张卡：多来源时每台 Wi-Fi 相机那一行下面有「全部 / 卡 1 / 卡 2」，各选各的（A 看卡 1、B 看卡 2），按机身记住；可选「按卡槽分子文件夹」（「α7 V/卡 2/」）；两张卡同时记录时只导卡 1 上的那份 | ✅ v0.5，模拟相机实测 |
| 菜单栏常驻：关闭窗口后留在菜单栏，导入照常进行；菜单栏面板显示当前来源、新照片数、插着的卡；可设登录时打开（只显示菜单栏图标） | ✅ v0.6 |
| 插卡自动打开：插入相机存储卡时打开导入窗口（已开着别的来源就同时打开，正在导入时只发通知），也可设为仅通知或不处理 | ✅ v0.6，模拟卡实测 |
| 相机上线通知：连过的相机开机、连上同一网络后约 30 秒内发通知「“a7 V”已上线」，点通知就连接（已开着别的来源就同时连接）；只敲一下端口，不建立会话，所以不显示张数 | ✅ v0.6，模拟相机实测（含点通知连接） |
| 自动导入：「设置 › 通用」里打开「连接过的相机开机后自动导入新照片」，或把「插入相机存储卡时」设为「自动导入新照片」；在后台连接 / 读卡，只导未导入过的照片（视频不自动导入，需要时手动选），开始前倒计时 10 秒（点通知或菜单栏面板可取消），按当前的导入方式、存放位置、备份、命名设置进行（C1 会话、LrC 收藏夹按命名模板起名，当天同名会话已存在就加进去）；不删除卡上的照片；备份磁盘未连接、空间不够、LrC 插件有问题时不导，发通知说明；导完发通知 | ✅ v0.6，模拟相机和模拟卡实测（文件夹、C1 新建会话、加入当天已有会话；LrC 未测） |
| 按创意外观套 Look（可选，「设置 › 软件 › Capture One 会话」）：导入到 C1 会话后，读 RAW 厂商信息 0xb020 里的创意外观（Standard→ST、Portrait→PT、Neutral→NT、Vivid→VV、Sepia→SE，VV2 / FL / FL2 / FL3 / IN / SH / BW 直接是代号），把 ICC 配置文件设为「<机型> Look-ST」等（自己装在 ~/Library/ColorSync/Profiles 的 `SonyA7M5-Look-ST.icc`），曲线设为 Linear Response；没装对应 Look 的保持原样；只处理 RAW | ✅ 实测（ST / FL / SH，FL / SH 为改过 EXIF 的测试文件；FL2、FL3 在文件里的写法是推测） |
| 按创意外观套 Look（LrC）：同一个开关，导入到 LrC 时插件读装在 Camera Raw 里的 Look XMP（`~/Library/Application Support/Adobe/CameraRaw/Settings`，按 crs:CameraModelRestriction 和名字「SonyA7M5 Look FL」匹配机型和外观），把它拼成 LrC 的 Look 设置（底层是它自带的 Linear Base DCP）；只给这次新加进目录的 RAW 设 | ✅ 临时目录实测（ST / FL / SH），插件 1.1.2 |
| 视频（读卡器）：视频单独存放（「设置 › 视频」，默认 ~/Movies/MiniDiT，文件夹模板默认「{M}.{D}-{事件}」），不进 C1 / LrC；片段按原名平铺，同名的 M01.XML 一起导；多台相机按相机分一层；代理（PRIVATE/M4ROOT/SUB/C0001S03.MP4）放进旁边的 Proxy/ 并改名为 C0001.MP4，DaVinci Resolve 导入原片时自动链接（可关）；XML 和代理一样校验、备份（备份文件夹里的「视频/」）、写进视频文件夹自己的 MHL；缩略图上显示时长、伽马和帧率（升格写成「120p→23.98p」），预览里显示分辨率、帧率、编码、伽马 / 色域、起始时间码、镜头；视频开关会记住 | ✅ v0.7，用 3 段 a7 V 实拍片段（S-Log3 / 709，H.264 / H.265 4:2:2 10bit）做的测试卡实测，ascmhl 复核通过 |
| 视频（Wi-Fi）：远程传输列表里同一次拍摄的代理（M4ROOT/SUB/C0001S03.MP4）挂在原片上，不再单独显示成一个片段，导入时跟着下载到 Proxy/；相机不提供 XML 文件，但 MP4 末尾的 meta 盒子里内嵌了一字不差的同一份：浏览时只读 MP4 最后 64 KB 显示时长、伽马、帧率等，导入后从下载好的 MP4 切出来存成 C0001M01.XML（读卡器上缺 XML 的片段也这样补）；XML、代理一样校验、备份、写进 MHL | ✅ a7 V 真机实测（C2682：原片 68 MB + 代理 17 MB + XML，8 秒；ascmhl 复核通过） |
| Wi-Fi 视频只导代理（底栏「…」菜单或「设置 › 视频」）：通过 Wi-Fi 导视频时只下载代理（Proxy/C0001.MP4）和 XML（读原片末尾内嵌的那份），原片留在卡上，位置和完整导入一样；一样校验、备份、写 MHL；选中大小按代理算；不记进导入记录，缩略图标「仅代理」（读卡器上同一张卡也认得出）；之后用读卡器导原片时进同一个文件夹，已有的代理和 XML 核对一致不再复制 | ✅ a7 V 真机实测（C2622：代理 487 MB 38 秒，完整原片要 10 分半；再用读卡器补原片，代理和 XML 记为 verified，ascmhl 复核通过） |
| 机内星级和 Shot Mark：照片读文件开头 16 KB 的 XMP（xmp:Rating，ARW 和 HIF 都有），缩略图左上角显示 ★，RAW+HIF 取打过的那个；视频读片段 XML 的 KlvPacketTable（「_ShotMark1」「_ShotMark2」带帧号），缩略图显示「◆ 2」，预览里列出时间点 ；导入时带过去：C1 会话里同名变体设星级（AppleScript），LrC 插件设星级（-1 设为排除，插件 1.1.3），Resolve 加蓝色标记「Shot Mark 1」，FCPXML 写 marker | ✅ Wi-Fi 实测（a7 V：DSC06647 ★★★ → C1 测试会话 3 星；C2686 两个 Shot Mark（第 384、668 帧）→ Resolve 测试项目两个标记，FCPXML 通过 DTD）；读卡器、LrC、FCP 里导入未实测 |
| 重新读取（⌘R，或来源卡片上的 ↻）：重新列一遍相机 / 卡上的文件，连上之后新拍的照片才会出现；保留选择和查看的日期 | ✅ |
| 卷号：每导入一次、每种机型一卷（A001、A002…，第二种机型从 B001 开始，字母按机型第一次出现的顺序给），卷号跟着片段记住（续传、只导代理后再导原片都沿用原来那卷）；视频文件夹模板可用 {卷号}（如「{M}.{D}-{事件}/{卷号}」）；交给 Resolve 时写进元数据的 Reel Number 和 Roll Card #（Reel Name 由 Resolve 按项目设置从文件名推出，脚本改不了），交给 FCP 时写进卷名（com.apple.proapps.studio.reel） | ✅ v0.8，实测：Wi-Fi 导入 a7 V 两段片段 → 同属 A001、存进「10.28/A001/」，MHL 写在卷文件夹里；Resolve 测试项目里 Reel Number / Roll Card # 为 A001；FCPXML 通过 DTD 检查（FCP 里导入未实测） |
| 加入 DaVinci Resolve：「设置 › 视频」打开「导入后加入 DaVinci Resolve 当前项目」（装了 Resolve 才显示）；导完通过 Resolve 的外部脚本接口，在当前打开的项目里每个视频文件夹建一个媒体夹（已有同名的就用它）并导入片段，已在媒体夹里的不重复导；Resolve 自动认出「Proxy」里的同名代理，没认出的再链接；可选「设置片段的输入色彩空间」（默认开）：按 XML 里的伽马给 S-Log3 / S-Log2 / HLG 片段写输入色彩空间（RCM 写“S-Gamut3.Cine/S-Log3”，ACES 写 IDT），不套 LUT，项目没开色彩管理时不写、发通知说明；Resolve 没开时先打开它；需要在 Resolve 偏好设置里把「外部脚本使用」设为「本地」 | ✅ v0.8，Resolve 21.1 实测（Wi-Fi 导入 a7 V 片段 → 测试项目的「10.28」媒体夹，代理已链接；再跑一次不重复） |
| 交给 Final Cut Pro：「设置 › 视频」打开「导入后交给 Final Cut Pro」（装了 FCP 才显示）；导完生成 FCPXML 用 FCP 打开，每个视频文件夹一个事件，片段原地引用、不复制进资源库，代理作为 FCP 的代理媒体一并链接，机型、伽马、帧率、镜头写进片段元数据；可选「设置片段的 Log 处理」（默认开）：S-Log3 片段选用 FCP 内置的 Log 处理（customLUTOverride：S-Gamut3.Cine 写“35 (Sony_SLog3_SGamut3Cine_v2)”，S-Gamut3 写“36 (Sony_SLog3_SGamut3)”，编号取自 FCP 12.4 自己导出的 XML；S-Log2 的编号未核实，暂不写）；之前导过的片段不重复交 | ✅ v0.8，FCP 12.4 实测（资源库 468 KB，原片和代理都是指向 MiniDiT 文件夹的链接） |
