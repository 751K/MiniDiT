# MiniDiT 产品规划

## 一句话

**从相机到电脑这一段，交给 MiniDiT。** 素材可以从两个来源来：
- **Wi-Fi**：相机连上网络，不用拔卡，适合日常和照片。
- **读卡器 / 本地卡**：适合大批量照片和视频原片。

MiniDiT 把素材安全地拷到 Mac，按你的习惯建好项目，交给你常用的后期软件或剪辑软件。

## 用户是谁

| 用户 | 典型情况 | 最在乎什么 |
|---|---|---|
| **独立摄影师 / 进阶爱好者**（主要用户） | 一两台机身。拍完回家或回工作室导片，用 C1 或 LR 修图 | 省事：别让我插卡、挑文件、建文件夹、起名字 |
| **婚礼 / 活动 / 商业摄影师** | 两三台机身，一天拍很多，经常有助理 | 别丢片、别重名；几台机身的照片能合到一起，按时间排好 |
| **现场助理 / 小团队 DIT** | 拍摄间隙把素材导出来备份，给客户或修图师 | 可验证：两份备份，有校验，有报告；格卡前能放心 |
| **拍视频的创作者**（后期） | 照片和视频混拍，视频文件很大 | 视频和照片分开放；大文件传得稳 |

我们不做：图片管理软件、修图软件，也不替代 Photo Mechanic 那样的专业选片工具。MiniDiT 只负责「从相机到电脑」这一段，并把这一段做到最省事、最可靠。

## 使用场景和需求

### 场景 1：拍完回家，导今天的片（最常见，最先做好）

> 「回到家，相机还开着，我想直接在 C1 里看到今天拍的东西，开始挑片。」

- **想要的结果**：打开 MiniDiT 后几下点击，C1 里就出现一个「11.4-公园」会话，里面是今天所有新拍的照片。
- **现在的痛点**
  - 每次都要点「搜索相机」，再点「连接」。
  - 进去以后要一张张点缩略图来选。
  - RAW 和 JPG 各占一格，数量对不上。
- **需要的功能**
  - 自动连上上次用过的相机。
  - 以「天」为单位勾选，默认选中没导入过的。
  - RAW 和 JPG 合成一格显示。
  - 会话名自动填好日期，内容名可以从最近用过的里面选。
- **衡量标准**：从打开 App 到开始下载，不超过 3 次操作，而且不用碰缩略图。

### 场景 2：出去玩了几天 / 一天拍了好几场

> 「旅行回来，5 天的照片，我想每天一个会话；有一天拍了两场，要分开。」

- **想要的结果**：多天的照片一次导完，自动分成多个项目；同一天里也能按时间段拆开。
- **需要的功能**
  - 多选几天时，可以选「每天一个项目」或「合成一个项目」。
  - 同一天里按时间间隔自动分组，比如两次拍摄相隔 2 小时以上就分开，每组可以单独命名。
  - 大图预览，用来判断这一组拍的是什么。
- **衡量标准**：5 天的素材，不超过 1 分钟就能设置好并开始导入。

### 场景 3：只想挑几张

> 「刚拍完，想先导几张 JPG 发给朋友，不想全导。」

- **需要的功能**
  - 和访达一样的选择方式：单击、⌘ 单击、⇧ 连选、框选、⌘A、方向键。
  - 按空格看大图，在大图里直接选中。
  - 可以只导 JPG。
- **衡量标准**：挑 10 张不连续的照片，不用一张张去点小圆圈。

### 场景 4：两台相机拍同一场

> 「婚礼上主机和副机都在拍，回来想把两台的片放进同一个会话，按时间排好。」

- **现在的痛点**
  - 一次只能连一台相机。
  - 两台机身都有 DSC00001，文件会撞名。
  - 两台相机的时间可能差好几分钟。
- **需要的功能**
  - 同时连接多台相机，导进同一个项目。
  - 文件名可以加相机前缀，或者按相机分子文件夹。
  - 提醒两台相机的时钟差了多少。
  - 能看出每张照片是哪台相机拍的。
  - 相机可以改名，比如「主机 A7 V」「副机 A7C II」。
  - 每台相机单独设置，比如副机只导卡 1。
- **衡量标准**：两台相机一起导，没有重名，按拍摄时间排好。

### 场景 5：格卡前确认安全

> 「客户的片，我要确认至少存了两份、没有坏文件，才敢把卡格式化。」

- **需要的功能**
  - 下载时做校验。
  - 同时写到第二块盘，两份都通过校验才算完成。
  - 每个项目附一份导入报告。
  - 相机里的每个文件都标出状态：已备份两份 / 一份 / 未导。
- **衡量标准**：看一眼就知道这张卡能不能格。

### 场景 6：不是每个人都用 C1

> 「我用 Lightroom Classic。」「我用 Bridge 看片，DxO 修图。」

- **需要的功能**：导完以后交给用户选的软件。

  | 软件 | 能做到的程度 |
  |---|---|
  | Capture One | 新建会话，照片直接出现在会话里（已实现） |
  | Lightroom Classic | 自动导入目录，并建一个同名收藏夹（需要装一个 LrC 插件） |
  | Bridge / DxO PhotoLab | 下载到项目文件夹，然后在软件里打开这个文件夹 |
  | 只存文件夹 | 按命名模板建文件夹 |

- **衡量标准**：换成 LR 的用户也能在几下操作之内完成导入。

### 场景 7：素材太多，插卡导更快

> 「今天拍了 2000 张，外加一堆视频，Wi-Fi 太慢了，我直接插读卡器。」

- **想要的结果**：插上卡，后面的体验和 Wi-Fi 一样，包括按天浏览、导入记录、建项目、校验和备份，只是更快。
- **需要的功能**
  - 识别插入的索尼卡，看 DCIM 和 PRIVATE/M4ROOT 目录。
  - 导入记录和 Wi-Fi 共用。用 Wi-Fi 导过的文件，插卡时同样显示「已导入」，反过来也一样。
  - 插卡时自动弹出 MiniDiT。
  - 导完可以安全推出卡。
- **衡量标准**：速度接近读卡器的上限；同一个文件不会因为换了来源就重复导入。

### 场景 8：回到家就自动开始（锦上添花）

> 「相机一开机、连上家里 Wi-Fi，Mac 就提醒我有新照片。」

- **需要的功能**
  - 常驻菜单栏，发现连过的相机上线就发通知：「A7 V 上有 52 张新照片」。
  - 点一下通知就进入导入。
  - 可以设置「自动导入到当天的项目」。

### 场景 9：拍视频（阶段待定，见下面的「视频」一节）

> 「拍了一天 S-Log3，回来要把素材备份两份，在 Resolve 里建好项目，给剪辑师一份带校验的盘。」

## 优先级

按「多少人会用到 × 多久用一次 × 现在有多痛」排序：

| 版本 | 解决的场景 | 内容 |
|---|---|---|
| **v0.2 省事** ✅ | 场景 1、3、7 | 自动连上次的相机；按天勾选；RAW 和 JPG 合成一格；访达式选择；大图预览；最近用过的内容名；**读卡器作为第二个来源** |
| **v0.3 放心** | 场景 5 | 校验；断线续传（掉线自动重连、中断后继续导入已经做了；单个文件的断点续传还没做）；双备份；导入报告；每个文件的备份状态 |
| **v0.4 多场次 + 多软件** | 场景 2、6 | 每天或每场一个项目；按时间间隔分组；LrC / Bridge / DxO 适配；命名模板 |
| **v0.5 多相机** | 场景 4 | 多台同时连接；相机列表和改名；防重名；时钟提醒；每台相机单独设置 |
| **v0.6 自动** | 场景 8 | 菜单栏常驻；相机上线通知；插卡自动弹出；自动导入 |
| **视频（待定）** | 场景 9 | 见下一节 |
| **v1.0 给别人用** | — | 签名、公证、安装包、自动更新；首次使用引导；多机型验证 |

> 导入记录里加上相机序列号这件事，虽然是给场景 4 用的，但要在 v0.2 就先做，免得以后迁移数据。

## 视频（阶段待定）

视频的 DIT 重点和照片不一样。照片要的是「省事」，视频要的是：数据量大、元数据多、不能出错，最后交给剪辑软件。

1. **数据量**
   - XAVC HS 4K 一小时 45–90 GB，XAVC S-I 可以到约 270 GB。所以原片主要走读卡器。
   - Wi-Fi 适合先拉代理（SUB/）和 XML，用来浏览和粗剪。远程传输能不能读到代理文件，需要真机验证。
2. **不改名、保留结构**
   - 原片、XML、代理、缩略图靠文件名互相关联，不能改名，也不能加前缀。
   - 默认保留 `PRIVATE/M4ROOT` 结构。
   - 多机位用卷号区分（A001 = A 机第 1 张卡）。
   - MP4 里的陀螺仪数据要完整保留，Gyroflow 要用。
3. **校验和报告**：xxHash64 或 MD5 校验，加上 ASC MHL 报告。两份备份都通过才算完成。
4. **按片段浏览**
   - 显示时长、分辨率、帧率、编码、时间码起止、伽马和色彩空间（S-Log3 / HLG / S-Cinetone）、升格。
   - 打点信息能不能读，待确认。
   - 这些数据都来自 XML，可以先拉 XML 再决定拷哪些。
   - Log 缩略图可以套 LUT 预览。
5. **两张卡**
   - 「同时记录」时两张卡的内容重复：要去重，或者把卡 2 当成核对用的备份。
   - 「接力记录」时一条片段跨两张卡。
   - 照片同样有「同时记录」的问题。
6. **交给剪辑软件**

   | 软件 | 做法 |
   |---|---|
   | DaVinci Resolve | 脚本接口：建项目和 bin，按天 / 机位分好，导入素材，可以套 LUT |
   | Final Cut Pro | 生成 FCPXML |
   | Premiere | 脚本或插件 |
   | 只存文件夹 | `项目/日期/卷号/` |

7. **长时间传输**
   - 开始前检查剩余空间。
   - 传输期间阻止 Mac 休眠。
   - Wi-Fi 传输时提醒相机电量和自动关机设置。
   - 大文件要能断点续传。
8. **外录音频**（以后再做）：从读卡器导入录音机的 WAV，归进同一个项目。

## 需要找用户确认的问题

- 其他摄影师主要用哪些后期软件？LrC 和 C1 各占多少？用 Photo Mechanic 的人多不多？
- 「每天一个会话」和「每场一个会话」，哪种更常见？会话命名习惯有哪些？
- 双备份一般备份到哪里：移动硬盘、NAS，还是网盘同步文件夹？
- 能接受全自动导入吗，还是更想要先提醒、再手动确认？
- 在家里导片时，Wi-Fi 的速度能接受吗？导多大的量会觉得太慢，开始想拔卡？

## 附：技术上的配套

- **架构分三层**：相机连接（每台相机一个会话）→ 下载队列（校验、备份、续传）→ 目标软件适配器（`ImportTarget`）。
- 「拍摄项目」是统一概念：在 C1 里对应会话，在 LrC 里对应「文件夹 + 收藏夹」，在其他软件里就是一个文件夹。
- ~~拆开 `AppModel.swift`~~：已按职责拆成 `AppModel`（状态）+ `+Source`（相机 / 读卡器连接、重连）+ `+Library`（读卡、筛选、选择、缩略图、预览）+ `+Import`（导入流程、C1）；单个文件的导入在 `FileImporter`，v0.3 的校验和第二份备份加在那里。
- 模拟相机支持一次开多台、设不同的序列号，用来测多相机。
- 来源也做成适配器（`MediaSource`）：Wi-Fi 相机和读卡器 / 本地卡各一个，导入记录按「相机序列号 + 文件」统一记，不区分来源。
- 待验证的协议能力：
  - 远程传输的列表里有没有星级、保护标记。
  - SDIO 能不能给相机校时。
  - Wi-Fi 下实际能跑到多快。
  - 远程传输能不能读到视频的代理和 XML。
- 钥匙串服务名、导入记录目录和 Bundle ID 还用旧名 `SonyImport`，正式发布前统一迁移。
