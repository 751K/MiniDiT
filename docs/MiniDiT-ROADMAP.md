# MiniDiT 产品规划

更新：2026-11-10。本文是后续产品取舍与开发顺序的依据，描述的是目标设计，不代表全部功能已经实现。现有能力与实测范围以 [功能清单](MiniDiT-FEATURES.md) 为准；此前按版本排列的规划保留在 [历史路线图](archive/MiniDiT-ROADMAP-before-2026-11-08.md)，不再作为当前优先级。

当前状态：P0 已基本实现；P1 已开始，首批落地“项目结果与补备份”：持久导入记录、逐文件/逐副本核验依据与时间、项目内查看结果、从现有可信文件补备份。多目标配置、逐目标结果与补备份现已实现；可读交接包已接入；独立复核入口仍未完成。真实磁盘拔插、相机与后期软件流程继续按实测范围验收。

## 1. 产品要负责的结果

**让拍摄素材可靠地落到用户指定的位置，尽快进入后期；需要交给别人时，能说清交了什么、存在哪里、核验到了哪一步。**

产品面向摄影与视频创作者，以素材导入、整理、校验、备份与后期交接为核心，品牌适配逐步扩展。当前版本仅适配 Sony α，其他品牌尚未适配；介绍产品目标时使用通用的“相机”，说明当前兼容性时明确版本范围，不把计划写成已支持。

个人拍摄首先要省事，团队交接首先要有依据，但这不是两类互斥的人。同一个独立摄影师，今天可能导几张旅行照片，明天就要交给客户两块素材盘。因此，产品围绕任务提供推荐，不围绕身份授予能力。

MiniDiT 的核心责任从发现相机或存储卡开始，到素材落盘、所需副本完成、后期软件接收或交接材料生成结束。导入后保留记录，允许补备份和复核，是这段责任的延续。

“快速修改”意味着让用户尽快在自己熟悉的 C1、LrC、Resolve 或 FCP 中开始工作。MiniDiT 不因此增加修图、剪辑或调色界面。照片与视频都可能需要严格交接，也都可能只想快速导入；不把媒体类型当成工作强度。

## 2. 当前最需要解决的产品问题

1. **概念相互牵连。** P0 已把 MiniDiT 自己的素材归属统一为“项目”，但历史数据、C1 专有会话、帮助文案和实际使用路径仍需保持一致，不能只完成标签替换。
2. **模式承诺大于实际差异。** 目前个人/团队主要改变卷号相关默认规则、自动导入和删除偏好，还没有完整的多副本交接闭环。
3. **完成的含义不够精确。** 文件传完、通过一次校验、当前副本可访问、所需备份齐全、成功交给后期，是不同事实。
4. **缺少事后补全。** 已有多目标备份及按目标补齐缺失文件，可读交接报告已接入，应用内独立复核仍待完成。
5. **规划堆积。** 旧路线图把大量专业名词和功能装进后续版本，没有清楚区分核心闭环、可选增强和暂不承担的工作。

缩略图副本检查仍通过文件存在及大小更新数量（`refreshCopies()`），不能把它当成内容复核。新增项目导入记录另外保存逐文件、逐副本的核验依据与时间；结果页的“当前可访问”只检查可读性，与历史核验分开显示。多目标与卷身份检查共用这套记录；可读报告已接入；下一步增加独立复核。

## 3. 三个主要用户任务

| 任务 | 用户希望完成什么 | 产品应省掉什么 | 必须留给用户的决定 |
|---|---|---|---|
| 快速导入并开始后期 | 今天的新照片进入 LrC，视频进入自己的视频目录或剪辑软件 | 重复选软件、填目录、命名、找未导入项 | 导哪些、放哪里、是否备份、是否自动开始 |
| 整理一场拍摄 | 多机、多卡、跨天素材能归到同一件事，照片视频按各自习惯存放 | 重名处理、重复下载、重复填写项目名 | 归入哪个项目、是否合并、目录规则、保留哪些格式 |
| 准备素材交接 | 指定几份副本，知道哪些完成，交出清单并能再次核对 | 手记文件数、逐盘检查、从头重拷、手工拼报告 | 交接范围、目标盘、必需副本、何时复核和交出 |

优先服务前两个任务，同时把第三个任务的最小闭环做好。团队成员、权限、云端同步、审批不属于“素材交接”必然需要的能力。

## 4. 个人和团队：推荐工作方式，不是两套产品

保留用户理解得了的“个人创作 / 团队交接”说明；行为分别围绕“快速开始后期 / 准备交接”。不再把选择身份作为进入软件的必经步骤。

| 项目 | 快速开始后期（个人常用） | 准备交接（团队常用） |
|---|---|---|
| 起点 | 沿用上次位置和后期软件，突出新素材 | 确定本次范围与需要完成的目标盘 |
| 整理 | 先选择或新建项目；目录默认按拍摄日期，也可按项目名称整理 | 可按项目、来源、卷号组织，但不强制每个团队按卷号 |
| 备份 | 自行决定；启用后遵守同样的校验标准 | 显式列出每个目标与是否为本次交接所必需 |
| 主画面重点 | 剩余时间、何时可以开始后期 | 各盘进度、未完成项、复核结果和清单 |
| 自动化 | 记住偏好；自动导入由用户主动开启 | 推荐手动启动；仍允许有稳定流程的团队开启自动导入 |
| 完成 | 工作副本可用，可打开后期；备份继续显示进度 | 本次声明的范围、必需副本和复核条件均满足 |

两者使用同一套导入、校验和备份能力。个人可增加多个备份目标并生成报告；团队也可先取几张照片。不增加“个人版更弱的校验”，不以身份隐藏设置。

推荐配置只在用户选择应用时生效，显示将改变的项目；不覆盖自定义规则，不追溯修改过去的导入。已有用户升级不重走整套引导。多备份与交接闭环未上线前，现有模式不得宣称已经提供这些保障。

## 5. 对用户可见的概念要少，边界要清楚

| 概念 | 含义 | 用户什么时候需要理解 |
|---|---|---|
| 来源 | 相机、卡或本地卡目录 | 选择素材时 |
| 导入记录 | 一次实际执行及其文件、目标、结果 | 找文件、继续中断、补备份、查异常时 |
| 项目（导入目标） | 把同一件事的多次导入归在一起，如“周末婚礼” | 选择导入目标、浏览已导入内容时 |
| 存放位置 | 真正写入的目录；照片和视频可以不同 | 导入前随时可见 |
| 交接清单 | 对指定素材和指定副本在某时刻的结果说明 | 准备交给他人时 |

自 2026-11-09 起，MiniDiT 自己的界面归属统一称“项目”，C1 的专有名词仍保留为“Capture One 会话”。普通导入必须归属用户明确选择或新建的项目；启动时不自动选择最近项目，移除当前项目后也不自动改选其他项目。未选项目时底栏显示“新建项目”，点击后打开新建窗口，取消后不创建项目、不传输文件。用户也可以在侧栏选择已有项目后继续导入。

自动导入同样要求有已选择的项目，不再按日期隐式建立项目或绕过项目记录。续传沿用原任务中冻结的项目、路径及整理规则。直接拖到桌面或其他访达文件夹是独立的文件导出，可以不选择项目，不写入项目导入记录。

新建项目窗口提供日期、事件和照片/视频保存位置；所选目录按各自规则实时预览。取消不保存目录修改；确认“新建并导入”后，仍须通过备份、空间和后期软件检查。

项目负责素材归属，不强制搬动文件，也不要求照片视频放进同一目录。照片和视频继续使用各自的存放位置和目录规则；用户可在项目内集中查看分散存放的文件。项目实际同时包含照片和视频时，可在项目下分类查看。

### 来源身份（2026-11-09 已接入）

- 机身、卡/目录、当前连接和导入批次分别记录。有效序列号才建立机身身份；缺失或占位序列号不以型号、IP 代替。
- 读卡器来源独立保存卡名称、卷 UUID 和容量；同名不合并。重复标识、容量变化或缺少稳定标识时由用户确认，仍可继续导入。不往卡上写身份文件。
- 普通本地目录使用卷和目录标识，不能把同一磁盘上的所有测试目录当成同一张卡。
- 卡类型仅依据当前卷的 I/O 介质特征记录，不使用读卡器型号、容量或卷名推断。SD 协议信息不能确定 SD/microSD 外形；通用 USB、NVMe 不足以确定 CFexpress，更不能区分 A/B。未提供明确特征时显示“未识别”；真实读卡器的覆盖范围仍待实测。来源信息省略识别方式，机身序列号仅在 Wi-Fi 来源显示。
- Wi-Fi 记录机身与卡槽；卡槽不等同实体卡身份。卷 UUID 是文件系统标识，不承诺对首次单独出现的克隆卷作硬件级鉴别；用户始终可更正归属。
- 拍摄机身按实际文件元数据记录，不把卡上第一张照片的机身套到所有素材。导入时冻结身份信息，之后改名或补备份不改写旧记录。

## 6. 导入流程：信息足够，决定尽量少

主流程：**连接设备 → 筛选素材 → 选择或新建项目 → 确认去向 → 导入 → 开始后期或查看交接结果。**

首次使用只收集完成第一次导入所需的信息：照片/视频、保存位置、需要打开的软件、是否添加备份。默认按日期整理并保留原文件；普通导入前必须选择或新建项目，模板、卷号和色彩设置可稍后调整。不能因为没选完团队流程就无法浏览卡或拖出文件。

照片与视频保持相同的设置顺序：

1. 存到哪里与如何建文件夹。
2. 导入后交给哪个软件；“仅存文件夹”作为最直接的选项。
3. 选择了具体软件后，展开它的必要选项。

C1 新建会话决定照片实际写入 Capture，这个例外要直接展示最终路径，不能同时显示一个不会生效的独立照片路径。界面可以继续使用熟悉的“导入至”入口，但底层必须区分实际文件位置和后期软件接收动作，避免软件接收失败被误认为文件丢失。

主界面底栏只常驻：所选数量/大小、照片/视频去向摘要、备份摘要、导入按钮。点摘要查看明细，模板等低频设置不挤进底栏。保持现有顶部设置标签样式；本规划不要求另做一套视觉设计。

选择与刷新规则：

- 照片/视频偏好独立，照片的 RAW/JPG 偏好也独立。切换只影响新计划，不改变已开始的任务。
- 筛选条件始终可辨认，并可一键清除。“全选”说明选择的是当前筛选范围，不能让用户误认为整卡。
- 自动刷新保留用户选择；新发现文件不悄悄加入已经确认的导入批次。自动导入作为用户单独开启的行为处理。
- RAW+JPG 可以一格展示，结果同时报告素材数和实际文件数；视频明确原片、代理、XML 的覆盖情况。
- 拖到 Finder 是临时取文件的便捷动作；不弹一套导入向导，也不计作已完成计划备份。以固定说明和结果记录表达差异，不每次打断。

## 7. 自主权与限制的边界

**用户决定目的和取舍，产品负责执行一致、状态真实、默认不破坏已有东西。** 允许一种做法，不等于把它描述为满足了另一种承诺。

| 情况 | 产品处理 |
|---|---|
| 只想存一份 | 允许，显示“一份已保存”；不强制第二块盘，不渲染成“交接要求已完成” |
| 必需备份盘不在 | 允许明确选择先做可用目标，保留待补任务；仍显示交接未完成，可取消或修改本次要求 |
| 想改这次设置 | 提供“仅本次”；更新常用偏好需明确选择，不把临时例外悄悄记成永久默认 |
| 原文件同名 | 不静默覆盖；核验后复用一致文件，内容不同则保留两份并解决路径冲突 |
| 正在导入时改偏好 | 当前任务及续传沿用确认过的计划，新任务使用新偏好 |
| 想开始后期，备份还没完成 | 工作副本及依赖文件就绪后允许打开后期；继续展示备份未完成。备份须依据已核验原片，不能把后期改动混进原片基准 |
| 想删除原卡照片 | 默认关闭、单独主动开启，沿用可验证源文件和所选备份成功等条件；未知或失败时不执行。先前开启不应随模式切换偷偷扩大删除范围 |
| 想快速拷贝而不等完整流程 | 现有拖出途径可用；正常受管理导入保留基本完整性校验，不再增加算法、校验遍数等普通开关 |

只阻止确实无法完成的操作，例如目标不可写、目标路径会覆盖来源、需要的空间不足；不能因一个可选软件未安装而禁止存入文件夹。阻止某一步时给可行的下一步，避免只有“失败”按钮。

安全默认不是要求用户完成最大强度流程。用户可以取消尚未完成的备份要求，但记录需要保留本次变更，不能倒改旧报告。产品也不能提供一个按钮，把“未核验”改成“核验通过”。

## 8. 可靠性要表达事实，不能只给一个绿勾

每个副本至少分别记录三类事实：写入是否完成、当前是否可访问、上次内容核验的结果与时间。磁盘离线不等于文件丢失；查到文件不等于重新核验过；历史核验通过也不是永久承诺。

界面优先说具体结果：

- “工作盘：120 个文件已校验，可以开始后期。”
- “备份盘 A：120/120；备份盘 B：未连接，等待补备份。”
- “上次核验通过：11 月 8 日 14:20；当前磁盘离线。”
- “照片已保存，加入 Lightroom 失败；重试加入。”
- “已导代理，原片尚未导入。”

整体状态从本次范围和要求汇总，不能用其中一个副本的成功覆盖另一个必需副本的失败。存储结果、后期接收结果、交接条件分别显示；重试其中一步不要求从相机重新传一遍。

Wi-Fi 与读卡器的证据边界不同：读卡器能够读取源文件并比较；Wi-Fi 当前无法取得相机源文件校验值，不把接收数据及本地副本核对写成相机源文件端到端核验。技术细节在明细中解释，摘要仍用用户能理解的话。

不使用无条件的“可以格式化”。整卡检查必须覆盖被筛掉、未选择、未支持的文件和仅导代理的情况；只能报告“本次所选内容已完成”或在确有完整覆盖证据时报告“本次整卡检查已完成”，由用户决定是否清卡。整卡原样拷贝尚未实现，不能用媒体导入的完成状态代替整卡承诺。

## 9. 团队价值的最小闭环

### 9.1 多目的地与补备份

一个工作位置加可添加的备份目标，每个目标单独显示名称、位置、空间、状态，以及是否为本次交接所必需。不同时做两套“普通备份/专业备份”页面。

- 同一物理盘上的不同文件夹不算独立设备保护；可识别时说明，无法判断的 NAS、虚拟卷等标为独立性未知。允许用户存放，但不虚报独立副本数。
- 第一版先保证逐目标状态、取消、失败恢复和结果正确；不把“同时写全部目标”当产品承诺，性能调度随后优化。
- 单个盘失败不抹掉其他盘已完成的事实。补备份只处理缺失或核验失败的项，优先使用经过验证的现有副本；不能从未知状态副本悄悄修复所有盘。
- 目标离线、路径改变、文件被改动分别处理。允许重新定位目标并核对身份，不因盘名相同就认成原来的盘。
- 第一阶段覆盖系统已挂载、可读写的位置；不新增网盘登录、云端传输或 NAS 管理器。

### 9.2 人能看懂、离开 MiniDiT 仍可用的交接清单

最小交接包包括可离线打开的 PDF 交接清单、CSV 文件清单，以及已有的 ASC MHL 校验材料。ALE 仅在明确的接收方需要出现后追加，不先做报告模板编辑器。

清单至少包含：项目或导入名称、明确的交接范围、来源、素材/文件数、总大小、相对路径、原片/代理标识、各目标结果、核验时间与依据、失败/跳过/未覆盖项。以实际结果生成，不能用计划写入数充当成功数。报告文件路径避免泄漏无关的本机用户名和个人目录。

可提前生成未完成报告，标题明确“未完成”。最终报告绑定具体文件范围及核验记录；补拷或修改后生成新版本，保留先前版本。生成报告不代表接收方已经验收，不加入在线签收系统。

### 9.3 有目的的再次核验

写入时核验每份副本；新增副本时核验新增副本；交接前用户可对指定盘按已有基准再次读取检查。结果区分一致、缺失、内容变化、无法读取。没有可信基准只能建立新的基准，不能追认过去与原卡一致。

再次核验从导入记录和清单启动，不必连接原卡；如果原卡仍在，可另外比较来源。正常修图生成或修改的附属文件不混入原片一致性判断，新导出的成片不在原片交接范围内。

不默认机械地重复读盘三遍，不提供“校验次数越多越专业”的档位。读回核验也不能保证素材可解码、拍摄内容正确或硬盘未来永不损坏，产品描述不能越界。

## 10. 功能边界与设置预算

### 必须维护好

来源连接、选择与轻量预览、明确的导入范围、稳定传输、独立照片视频规则、保留原片关系、校验/恢复/备份、已支持软件的可靠交接。时间码、机内标记、代理和色彩信息服务于正确交给后期，不发展为编辑系统。

### 闭环做好后再按场景推进

整卡原样拷贝、监看 LUT、外录音频导入、接力记录片段、更多软件/机型适配。整卡拷贝若接收方必须保留卡结构，应作为明确的导入策略，不能和现有平铺整理暗中混用。跨机时间码同步、场/镜/条编辑、ALE 输出需实际交接场景证明收益再排期。

### 现阶段不做

修图剪辑工具、长期图库与全盘索引、云盘服务、账号/成员/权限/聊天/审批、项目排期、通用规则编程器、大量报告皮肤。免费不意味着产品应该承载所有摄影工作。

每个新功能进入开发前回答：它解决哪个重复发生的任务？现有工具是否已经完成？会增加多少日常决定？失败如何恢复？不使用它的人是否仍然走原来的短流程？

少数用户需要但边界清楚的功能可以放在情境操作或折叠详情里；不是每个功能都需要常驻一级设置。算法、内部流程和可自动推导的值不交给用户配置；已有模板能力放在高级设置，优先提供具体路径预览。

## 13. 验证产品，而不只是验证按钮

当前判断来自现有实现与本轮使用反馈，不冒充已完成用户研究。下一步用任务走查验证假设：

1. 新用户只导今天照片到文件夹，再在 LrC 中开始修图。
2. 同一张卡只导视频到 Resolve，照片随后导入另一个位置。
3. 已有项目跨两天、两台相机继续追加；不要求修改原有路径。
4. 用户筛出十张后导入，能准确说出其余素材是否已经保存。
5. 同一人从日常导入切换到客户交接，加两个目标后不丢失原偏好。
6. 备份盘拔出、源卡取走、软件未打开，用户仍能找出哪里成功、下一步做什么。
7. 文件被移动或内容变化，再次核验与报告如实反映。

记录首次成功导入率、开始导入所需决定数、到后期可用的时间、失败后能否自行恢复、用户对副本状态的理解是否正确。数据量和连接方式分开比较，不用“点击更少”掩盖传输或核验成本；不为这些指标额外强制账号或上传素材。

最重要的验收问题：**用户是否知道文件在哪里、哪些事情完成了、哪些仍未完成，并且能按自己的意愿继续。**
