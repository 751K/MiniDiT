# 交接清单

在项目中打开「导入记录与备份」，选择一次导入，再点「导出交接清单」。可导出所选导入或整个项目，按需填写整理人和交接备注，选择保存位置。导入或补备份运行中暂不导出，以免把正在变化的任务当作静态结果。

每次导出创建独立目录，包含：

- `report.pdf`：前半部分记录项目、导入、备份、来源、异常及校验材料；后半部分为素材清单。照片按缩略图排版，视频按卷号分组，用类似 FCP 的连续胶片条展示，整份清单使用相同的缩略图时间跨度（每幅 5 秒，不足 5 秒保留一幅），长片段的胶片条更长、短片段更短，片段按顺序排列，不同视频之间留有间隔；同一视频排满一行后继续到下一行；完整文件名排在胶片下方，长片段跨行时用锯齿表示延续，不添加“续”字，卷标题只保留卷号。时间码、格式和哈希等明细保留在 CSV 中。素材预览嵌入 PDF，接收方无需原软件即可打开。
- `files.csv`：UTF-8 文件与副本明细，每个实体文件在每个目标上的副本分别列行；未保存的文件、未完成的目标也会列出。字段区分实体文件名和关联导入项；来源地址与拍摄参数属于关联导入项。字段包括来源、卡档案/卷标识、卷号、已记录的时长/格式/时间码及其时基、字节数、XXH64、路径、历史核验与导出时状态。
- `manifest.json`：结构化快照，含完整来源字段、任务状态、用户备注及全部明细，便于其他工具处理。
- `checksums/`：从原目标取得的 ASC MHL 清单和可取得的同目录历史链。清单原文不改写；不是从报告里重新生成一份“看似已经核验”的清单。离线、权限不足或目标盘身份不符时明确记录未附入的材料。
- `README.txt`：文件用途及核验边界。

照片和视频优先读取当前可访问的工作文件，也可从记录内的备份生成预览。视频原片无法解码时可尝试可访问的代理，并注明预览来源。素材离线、已变化或系统无法解码时保留占位，不从未连接的相机重新下载，也不伪造图片。视频无已知时长时只尝试首帧，其余位置明确留空。照片清单中的长文件名可省略显示，视频胶片下方保留完整文件名并自动避让，CSV 保留全文。

## 对真实交接的取舍

接收人通常需要知道来源卡/卷是否遗漏、各目标分别完成了什么、哪些文件有问题，以及报告依据哪次复制与核验。Pomfort 的卸载与文件报告也分别记录来源、目标、文件数、大小、时间与核验信息；据此，本功能按来源、任务和目标组织，而不把几条“导入成功”的日志当作交接报告。[Pomfort 报告说明](https://pomfort.com/article/document-log-camera-backups-reports-silverstack-offload-manager/)、[Offload Manager 报告能力](https://pomfort.com/offloadmanager/features/)。

ASC MHL 用于保存文件校验与复制历史；可读报告与 CSV 服务于交接阅读，ASC MHL 保留给兼容工具复核，三者用途不同。[ASC MHL 规范与实施指南](https://github.com/ascmitc/mhl-specification)。

## 完成状态的边界

- 只覆盖报告范围内已记录的导入，不宣称扫描了整张卡。跨项目的任务仅列所选项目；同批 MHL 可能包含更大范围，会注明。
- 导入项和实体文件分开计数。RAW/JPG 是文件，代理和 XML 也计入实体文件；多份副本不重复计算素材总大小。整个项目包含的重复导入按导入记录累计，不当作去重后的项目素材统计。
- 历史校验与当前可访问性分开列出。导出时只检查可读性、大小及已知目标卷身份，不重算素材哈希；相同大小的内容变化需单独内容复核。
- Wi-Fi 来源无相机端源文件校验值，不冒充原卡端到端核对。只导代理时明确不包含原片。旧记录没有的参数和核验日期不补写。
- 保留源拍摄日期原文；UTC 字段是当时解析得到的时间，不表示机身时钟已校准。卷号是 MiniDiT 记录的整理卷号；卡档案 ID 不是卡硬件序列号。
- 目标路径数量不代表物理盘独立性或异地备份。画面、声音、同步、色彩和整卡目录结构 QC，以及接收方签收，都不由此报告自动承诺。
- 每次导出生成新 ID 和新目录，补备份后重新导出不会覆盖之前交出的版本。失败/取消只清理本次临时目录，不删除素材或旧报告。

## 验证

核心检查覆盖完整报告、离线/大小变化、同大小变化不冒充重算、项目范围过滤、失败占位行、仅代理、历史迁移位置、CSV 引号/换行/表格公式、PDF 分页及文本、MHL 历史附件、磁盘身份不符、5000 个导入项的完整 CSV 与预览分组、旧版本保留和取消清理。`--handoff-pdf` 使用真实示例照片和视频验证缩略图分页、两卷分组、连续拼接、换行续接及离线占位。应用层检查从实际照片/视频/代理/XML 导入生成报告，再移除原卡和工作副本、补齐目标、导出新报告，确认旧报告未被修改。

视频版式参考 [Apple 的 FCP 浏览器连续画面视图](https://support.apple.com/zh-cn/guide/final-cut-pro/verd00d3ae7/mac) 和 [自定义连续画面](https://support.apple.com/zh-cn/guide/final-cut-pro/ver7ff5e14b9/mac)：采用固定时间比例展开片段，缩略图下方显示文件名；报告不显示卷内片段数量、总时长或技术参数叠字。
